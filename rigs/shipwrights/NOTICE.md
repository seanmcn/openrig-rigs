# Notice

Shipwrights is built on Workshop with a review pair (`rigs/workshop-review-pair`) from
[mvschwarz/openrig-world](https://github.com/mvschwarz/openrig-world) at commit
`d544888b4c9973164e7986d7e0344a7ceca89a8c`, Copyright the OpenRig authors, licensed under the Apache License 2.0. The
licence is in `LICENSE`. These files are modified versions of Workshop's:

| File here | Workshop's file | What changed |
|---|---|---|
| `rig.yaml` | `rig.yaml` | Named `shipwrights`; seats of a role that can grow are numbered, in pods by role: `orch.lead`, `orch.peer`, `orch.clerk-1` and `orch.planner-1`; `dev.backend-1`, Workshop's builder, with the `builder-backend` profile, and `dev.frontend-1`; `quality.qa-1` and `quality.qa-2`, a QA seat for each builder in a pod of their own; `review.reviewer-1` and `review.reviewer-2`, Workshop's two reviewers renamed, from which the clerk pairs two, and `review.judge-1`; and `release.manager-1`. New are the peer, on either runtime, the clerk, the planner, the frontend builder, the second QA seat, the judge and the release manager. Each member names its role's profile for its runtime; the lead is every other seat's orchestrator but the peer's, its only `delegates_to` source, so stuck rows escalate to it, and the peer observes only the lead; the team settings and the team's shape are startup files for every seat, and the judge also gets `startup/review-pair-judge.md` and `startup/slice-spec.md`. |
| `bundle.yaml` | `bundle.yaml` | Minimum OpenRig 0.7.1; preconditions for a folder of several clones. |
| `configurations.yaml` | `configurations.yaml` | No Pi runtimes; every seat may run on Claude Code or Codex, each with its role's profile for that runtime; the recommended preset puts one code reviewer on each runtime. |
| `CULTURE.md` | `CULTURE.md` | QA passes a commit before review starts; adds each repository's own rules first, retrospective notes, skills a person types, publishing a judged slice through the release manager, merging only as the repository's `AGENTS.md` allows, and reporting a leaked credential; a row someone else waits on is finished when it's closed. |
| `startup/context.md` | `startup/context.md` | Works in a folder of several clones; reads each repository's `AGENTS.md` first; loads every registered context pack; reads the team settings; the clerk takes the person's goal, and with no goal the team waits. |
| `startup/lead-first-move.md` | `startup/lead-first-move.md` | The person's goals go to the clerk, which hands a clear one to a planner; the lead takes the work on by locking its cut, and settles a goal the clerk passes it as unclear, a question or in doubt; the planner cuts every goal into slices, one pull request per repository each, with dependencies; points stop and pause to the role file. |
| `startup/review-pair-builder.md` | `startup/review-pair-builder.md` | The clerk names the review pair for each slice, in place of a fixed pair; the builder hands a commit to them once QA passes it, not at the same time. |
| `startup/review-pair-reviewer.md` | `startup/review-pair-reviewer.md` | The clerk pairs two reviewers on different runtimes for each slice; reviewers keep apart from each other's proof as well as findings; the judge, not the lead, compares the two reviews; a reviewer holds its row on the slice, parked between commits, until the clerk releases it. |
| `startup/review-pair-lead.md` | `startup/review-pair-lead.md` | The judge compares the two reviews and the release manager reports them in the pull request, so the lead keeps only the case of reviewers on one runtime, which the clerk passes it. |
| `startup/review-pair-judge.md` | `startup/review-pair-lead.md`, its "Compare the two reviews" step | New, for the judge: compares the two reviews as Workshop's lead did, settles only a disagreement's first fix round, releases the pair through the clerk once the slice is judged, and records the comparison for the pull request. |
| `agents/shipwrights/agent.yaml` | `agents/workshop/agent.yaml` | Profiles select OpenRig's plugin, `using-the-tui-together` and the skills `skills.md` lists for their role, each declared as the team's copy and following its source on restore; Workshop's `lead`, `qa` and `code-reviewer` roles, its `builder` renamed `builder-backend`, and new `peer`, `clerk`, `planner`, `builder-frontend`, `judge` and `release-manager` roles; each role has one profile per runtime (`<role>-claude`, `<role>-codex`), which share its guidance and suggest a model and effort for that runtime; no Pi profiles or generated skill snapshots. |
| `agents/shipwrights/skills/using-the-tui-together/SKILL.md` | `agents/workshop/bundle-skills/using-the-tui-together/SKILL.md` | Its examples name this team's seats and rig; no notes for OpenRig versions older than this team needs. |
| `agents/shipwrights/guidance/lead.md` | `agents/workshop/guidance/lead.md` | The planner scopes every slice, and the lead reviews and locks its spec; the clerk does the routine coordination (assigning each slice a free builder, QA seat and review pair, relaunching each worker fresh when the judge or the lead releases it, the roster, the slice time limit and recording deliveries), takes the person's goals and routes a clear one to a planner, and passes back only goals its rules don't settle, overdue builds, completed missions with their pull requests and what its rules don't settle; a judge judges recorded proof and passes the lead only the hard or risky slices `startup/team-shape.md` lists, which the lead decides, telling the judge, which tells the builder; the lead may overrule the judge with a reason; waits, stop and pause, with a wait on a seat's row clearing when that row closes; a stop closes the builder's row first; the judge sends routine slices to a release manager with no row to the lead, and CI failures, conflicts and pull requests that fail together come back to the lead, which decides the fix or rebase; the lead takes the work on by locking its cut and closes the goal's row once its missions are complete; it finds work only when asked, offering three options; retrospectives. |
| `agents/shipwrights/guidance/builder-backend.md` | `agents/workshop/guidance/builder.md` | Renamed for the backend builder, whose guidance the frontend builder builds on; reads the repository's `AGENTS.md` first in every slice and runs commands from inside the worktree; `implement` and `tdd`; self-review with `ponytail-review`; QA passes each commit before review, and what each of its verdicts asks; blocks its row on each commit row it hands out, with a backstop timer, and names the row a new commit replaces; a canceled row means the slice was stopped; rebasing, after the pull request is open only when the clerk sends a rebase row; tells the judge, not the lead, that a slice is done; the release manager pushes; a retrospective note. |
| `agents/shipwrights/guidance/qa.md` | `agents/workshop/guidance/qa.md` | Checks each commit before the reviewers see it; the same first steps; generic test layers in place of OpenRig's own; records its result with `rig proof add`, choosing the verdict by what the builder should do next; claims each commit row and closes it once the result is sent, or as superseded by a newer commit; checks several pull requests together when the clerk asks, closing that row with the result for the release manager that asked; a retrospective note when something cost time. |
| `agents/shipwrights/guidance/code-reviewer.md` | `agents/workshop/guidance/code-reviewer.md` | The clerk names it for a slice as one of a review pair; the same first steps; three review skills on every change and the others only when the change calls for them; records its verdict with `rig proof add`, as `rev1-` and its member id, and sends it to the judge; claims each commit row and closes it once the verdict is sent, or as superseded by a newer commit; a retrospective note. |
| `agents/shipwrights/guidance/peer.md`, `clerk.md`, `planner.md`, `builder-frontend.md`, `judge.md`, `release-manager.md` | none | New: this team's own seats. |
| `agents/shipwrights/runtime/claude-activity-hooks.json` | `agents/workshop/runtime/claude-activity-hooks.json` | Unchanged. |
| `README.md` | `README.md` | Rewritten for this team. |

`skills.md`, `settings.md`, `startup/slice-spec.md` and `startup/team-shape.md` are this team's own.

its row in `skills.md` names, and each under its own licence, which sits beside it in its folder: MIT for most,

(`differential-review`, `sharp-edges`, `supply-chain-risk-auditor` and `agentic-actions-auditor`), whose copies, and
any changed copy you share, keep that licence and its attribution. None of this team's Apache-2.0 licence applies to
